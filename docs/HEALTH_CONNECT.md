# Health Connect phone bridge

This extends the existing FastAPI backend and Wearable sidebar. It reads actual records from
[Health Connect to Webhook](https://github.com/mcnaveen/health-connect-webhook), using its
[local HTTP API](https://github.com/mcnaveen/health-connect-webhook/blob/main/docs/local-http.md)
and [JSON schema](https://github.com/mcnaveen/health-connect-webhook/blob/main/docs/webhook.md).
It is a recorded-data reader, not a continuous watch sensor stream. Google Fit/Noise ownership
or sensor access is not inferred from a Bluetooth connection or a package name.

## First local connection without Cognito

1. Keep phone and laptop on the same trusted Wi-Fi. Start the Android app's local HTTP server,
   allow its Health Connect reads and check the app's current LAN IP/port. Never port-forward
   this server, expose it publicly or tunnel personal records to a public service.
2. In the repository root, with the Python environment installed, run:

   ```powershell
   .\.venv\Scripts\python.exe scripts/health_connect.py --configure-local --base-url http://PHONE_LAN_IP:8787 --check
   ```

   Replace PHONE_LAN_IP with the address displayed by your phone. This creates a random eight-hour
   local pairing key in ignored `.env` and `work/health-connect-pairing.txt`. It preserves existing
   secrets. The command prints only connection status, record counts and availability, never the
   key or measurements. `--hours` accepts1–24; repeat to rotate/renew a key and restart the backend.
3. If the Android HTTP server has authentication enabled, set `HEALTH_CONNECT_TOKEN` privately in
   root `.env` to its Bearer token. This phone token is never sent to the browser. Enable the
   app's authentication on a shared network; the adapter cannot switch it off. Plain LAN HTTP
   has no transport encryption; a Bearer token alone does not encrypt Wi-Fi traffic.
4. Install/reuse dependencies and start both local servers:

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements.lock
   npm --prefix frontend ci
   npm run dev
   ```

   If already running, restart the backend after configuration changes. The existing dev script
   binds the backend8000 and frontend5173 to127.0.0.1 and sets exact-origin CORS. Open
   http://127.0.0.1:5173, choose **Wearable**, copy the key from the private pairing file into
   **Local pairing key**, check session consent, and choose **Connect & read**. Do not paste
   any key into chat, Git, screenshots, browser env variables or a public deployment.
5. Select a date within the last seven days. Daily totals use the browser's IANA timezone.
   Vitals show the latest recorded measurement in the seven-day window, with its actual date.
   Refresh manually, or select60/120seconds. Automatic refresh is off by default, pauses in hidden
   tabs, does not overlap requests, and stops on errors/revocation. Disconnect clears browser
   records and key; switching sections clears the phone session. Renewing the key invalidates
   the previous key after backend restart.

The local pairing key is read-only for these three endpoints, expires server-side, requires
loopback client/Host plus an approved browser Origin, and derives the configured owner. It grants
no existing private route, journey, device-write or cloud access. Anonymous health reads remain401.
With Cognito later, configure the real owning user's verified `sub` and use ecoroute/read;
another user cannot read this phone. This private LAN adapter is deliberately rejected in the
AWS execution profile: a cloud Lambda cannot reach a private phone LAN address. A future cloud
bridge needs an authenticated outbound companion upload; no unsafe public tunnel is provided.

## Configuration (root .env, never frontend/.env.local)

| Name | Purpose | Sensitive | Requirement |
|---|---|---|---|
| HEALTH_CONNECT_BASE_URL | Fixed private IPv4 LAN target with explicit port | Configuration | Required; generated by local setup |
| HEALTH_CONNECT_TOKEN | Android server Bearer token | Yes | Required when phone authentication is enabled |
| HEALTH_CONNECT_OWNER_SUB | Authorized Cognito sub or generated local owner | Identifier | Required |
| HEALTH_CONNECT_LOCAL_ACCESS_TOKEN | Expiring local bridge pairing key | Yes | Local alternative to Cognito, generated |
| HEALTH_CONNECT_LOCAL_ACCESS_EXPIRES_AT | Key expiry, Unix seconds | No | Required with local key, generated |
| CORS_ORIGINS | Exact permitted frontend origins | No | Existing local dev script sets127.0.0.1:5173 |

`.env.example` contains names/placeholders only. Git ignores `.env`, work/, health records and
private files. No new AWS IAM permission, resource, paid service or cloud credential is used.

## Backend endpoints

All use `Authorization: Bearer <LOCAL_PAIRING_KEY_OR_COGNITO_ACCESS_TOKEN>`, derived ownership,
no-store responses and sanitized error envelopes. Phone URL/token cannot be overridden by requests.

| GET endpoint | Query | Response |
|---|---|---|
| /api/v1/wearables/health-connect/status | None | Ping/connection status, optional phone last sync, auth mode |
| /api/v1/wearables/health-connect/data | consent=true; days1–30(default7); cached=false | Normalized requested records, skipped count and quality warnings |
| /api/v1/wearables/health-connect/summary | consent=true; days1–30; selected_date=YYYY-MM-DD; timezone_name=IANA; cached=false | Eight metrics, source/time/unit/status, sleep sessions and calorie basis |

Use the exported OpenAPI in `docs/openapi.json` for exact schemas. Private Postman access_token
can hold a local key for **only** these endpoints; it does not authorize the rest of the collection.
Errors:401 missing/invalid/expired bearer;403 wrong owner/origin/scope/consent;422 invalid query;
429 read already in progress/phone rate limiting;503 phone unconfigured/unreachable;
502 rejected/invalid/oversized phone response;504 timeout. No raw provider error is returned.

## Parsing and scientific limits

- Units: BPM, blood pressure mmHg, SpO2%, steps count, sleep seconds, kcal and breaths/min.
  Source metadata is a package identifier or null, not a verified watch manufacturer. Only the
  nine requested arrays (active/total energy separately) are retained; other sensitive types
  are discarded. Unsupported schemas fail safely instead of guessing new field names.
- Payload `timestamp` is generation time, not observation time. `/health.lastSyncTime`, when
  present, is epoch milliseconds. `/latest` may be an incremental background cache, so it is
  explicit opt-in and cannot supply a daily steps/calorie/sleep total. Fresh root reads never
  silently fall back to the cache.
- Latest vitals are selected by record time, not array order. Bucket `avg/min/max` records are
  labeled averaged values. Conflicting latest values are unavailable. Old records stay labeled
  recorded/older, not live. Missing arrays do not establish that a permission was denied.
- Exact normalized duplicates are removed. JSON currently does not provide the Protobuf-only
  Health Connect record IDs; those IDs are not invented. Overlapping counts from competing or
  amended intervals cannot be reliably combined, so the daily total is null with a warning.
  Cross-midnight count/energy records are not proportionally split without supporting samples.
  Completed non-overlapping day records can be summed, but are not proof of full-day coverage.
- Total energy already includes active energy; never add the two. Unfinished/projected energy
  intervals ending in the future are excluded from actual daily totals. Prefer total records
  when present, otherwise explicitly label active energy.
- Sleep duration is the union of session intervals ending on the selected local day, including
  overnight sessions and any awake time inside them. It is not actual staged-asleep time or a
  sleep score. Day boundaries handle DST and use installed tzdata on Windows.
- The adapter bounds requests to6seconds/connect2seconds,4MiB and20,000 requested records;
  disables redirects/proxy environment; rejects public/metadata/credential-bearing phone URLs.
  No health response body, phone token or user request body is logged or permanently stored.
  Access logs are disabled by the local startup script. Other existing features are unchanged.
- No overall health score, activity score, battery, hydration or medically validated diagnostic
  value is inferred. Watch fields without actual input remain unavailable. Readings are not a
  causal explanation of pollution exposure.

## Verification and actual phone result — 2026-10-11

Run `scripts/health_connect.py --check --timezone Asia/Kolkata` for a redacted direct probe.
Then use the Wearable panel to verify backend authorization and rendering. Direct `/ping` and
`/health` returned200. App1.9.22 fresh seven-day response supplied one steps record and five
total-calorie records. Six requested records normalized, zero invalid records skipped. Today's
steps summary was available. Today's calories were unavailable because the interval was
unfinished/projected, rather than falsely represented as burned energy. Heart rate, blood
pressure, SpO2, sleep, resting heart rate and respiratory rate were absent. Last synchronization
time was not supplied. No actual measurement values are written into this report.

Local backend status/data/summary returned200 with pairing,401 without a bearer, and403 without
session consent. Existing Cognito APIs retain their protections. Hardware heart-rate/NoiseFit
export is still unverified; granting32permissions does not create records absent from Health
Connect. Open the phone's Health Connect data view to check which source apps actually write
each requested metric. A new reading will appear only once the source writes it and a fresh read
retrieves it. Phone IP changes require reconfiguration and backend restart.

Tests use explicit synthetic fixtures, never a fallback in the app. Backend covers parsing,
deduplication, overlapping records, DST, projected energy, sleep unions, cached/empty responses,
timeouts/disconnect/schema changes, owner/scope/consent and expiring local auth. Browser tests
cover all eight metrics, refresh, empty/error/retry, date changes, revocation and mobile layout.
